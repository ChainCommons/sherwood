# RFC P0-2-01 — scaffold the Tezos adapter workspace package

**Lane:** tezos · **TODO:** P0-2-01 · **Raised:** 2026-09-09
**Status:** blocked before implementation
**Owner of the fix:** Steward (workspace package setup and root test discovery)

## Reason for stopping

The P0-2-01 task pack explicitly instructs this lane:

> If the workspace needs a new package, add docs/rfc/P0-2-01.md and do not
> edit pnpm-lock.yaml or root package.json.

The shared preamble also requires an RFC and a stop when an API change
outside the lane's owned paths is needed. This RFC is the task pack's
explicit exception to those path boundaries. No provider implementation
ships with this request; P0-2-01 remains incomplete.

At main commit `acf78fe`, there is no `adapters/` directory or existing Tezos
package to extend. The workspace already includes `adapters/*`, but:

- `vitest.config.ts` discovers only `packages/*/test/**/*.test.ts` and
  `tests/**/*.test.ts`, so adjacent adapter tests would not run with `pnpm test`.
- Root `tsconfig.json` includes package sources/tests and root tests, but no
  adapter sources/tests.
- `pnpm-lock.yaml` has no Tezos adapter importer.

Adding unregistered source files would leave the adapter outside the existing
verification paths. This task pack calls for the workspace prerequisite to be
resolved before implementation.

## Requested prerequisite

1. Scaffold `adapters/tezos` as `@octc/adapter-tezos`, with TypeScript source
   exports and `build` / `typecheck` scripts following existing packages.
   Use a local `tsconfig.json` extending `../../tsconfig.base.json` and
   including `src/**/*` and `test/**/*`.
2. Record the package through a workspace install and commit the resulting
   lockfile entry. The client can use native `fetch`; no new external runtime
   dependency is requested.
3. Include `adapters/*/test/**/*.test.ts` in root Vitest discovery. Ensure root
   typechecking covers adapter sources and tests, either through the package's
   Turbo typecheck script or explicit root TypeScript include patterns.

The existing workspace glob is sufficient; no root package dependency or
script changes are requested. A dependency-free package may still pass a
frozen install before its importer is recorded; the missing importer alone
is not claimed to break CI.

## Implementation after the prerequisite

Keep the provider contract and TzKT implementation inside `adapters/tezos`.
Follow the `ChainProvider` interface in plan 07: provider identity, streamed
address operations with an optional time range, operation lookup by hash,
and token balances with an optional block. Keep raw provider payloads
separate from subsequent evidence persistence and `TechnicalTx` mapping
(P0-2-02).

The implementation will need deterministic pagination, bounded rate-limit
handling, an injectable HTTP transport for offline tests, and an explicit
error for any unsupported historical-balance request. It must preserve
operation groups and internal operations, accept public identifiers only,
and require no wallet credentials. Marketplace decoding and tax treatment
are outside P0-2-01.

Adjacent tests should consume the existing frozen JSON in `tests/adapters/tzkt/`
without modifying those files. Cover page boundaries and exhaustion, time
filters, rate-limit retries and exhaustion, HTTP failures, complete operation
groups, token balances, and a second mock provider implementing the same
contract. Verify that `pnpm test` discovers those tests and `pnpm typecheck`
checks the adapter before accepting the implementation.

## Unblocking

Land the workspace prerequisite, then resume P0-2-01 from the updated main
branch. This RFC does not complete the ChainProvider or TzKT client task.
