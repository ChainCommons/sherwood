# RFC P0-3-01 — two blockers found while indexing the France sources

**Lane:** france · **TODO:** P0-3-01 · **Raised:** 2026-09-08
**Owner of the fix:** Steward (`schemas/`, `packages/validate/`)

Filed per the shared preamble: both items are outside `jurisdictions/france`
and `jurisdictions/eu`, so this lane did not touch them. Neither blocks
P0-3-01 — the pack ships green with the workarounds below — but both will bite
the next contributor.

---

## 1. `unique-ids` treats a source-version's foreign key as a declaration

`schemas/source/source-version.schema.json` **requires** `source_id`: it is the
foreign key from a dated capture back to the source it is a version of, and
plan 05 §28 makes that chain the mechanism by which historical text survives.

`packages/validate/src/checks/unique-ids.ts` lists `source_id` in `ID_FIELDS`
and treats every occurrence as a *declaration*. So the moment a second document
legitimately references the same source, validation fails:

```
ERROR [unique-ids] …/versions/bofip-rppm-pvbmc-30-30-2019-09-02.yaml:
  duplicate source_id "fr-bofip-rppm-pvbmc-30-30",
  first seen in …/sources/bofip-rppm-pvbmc-30-30.yaml
```

The result is that **`source-version.schema.json` cannot be used at all**: any
pack that authors a version record fails CI.

`references.ts` already gets this right and shows the intended shape:

```ts
if (typeof record.source_id === 'string' && record.source_version_id === undefined) {
  declaredSources.add(record.source_id)
}
```

`unique-ids.ts` has the same carve-out for `jurisdiction_id`, via `declaresId`,
and needs the equivalent for `source_id`:

```ts
const declaresId = (field: string, doc: Record<string, unknown>): boolean => {
  if (field === 'jurisdiction_id') return typeof doc.jurisdiction_type === 'string'
  // A source version carries source_id as a foreign key, not a declaration.
  if (field === 'source_id') return doc.source_version_id === undefined
  return true
}
```

A regression test belongs next to it: a source plus two of its versions must
validate clean, and two *sources* claiming one `source_id` must still fail.

**Workaround used in P0-3-01.** No source-version records ship. Each dated
capture is modelled as its own `Source`, linked with `supersedes` /
`superseded_by` — which `references.ts` does validate. For BOFiP this is
arguably the more faithful model anyway, because BOFiP gives every dated
version its own stable identifier and URL
(`BOI-RPPM-PVBMC-30-30-20190902` vs `…-20240423`). It reads less well for a
statute, where the two rédactions of CGI art. 150 VH bis share one Légifrance
article id and only differ by a date-pinned URL. Once the check is fixed, the
statute pairs are the natural candidates to re-model as versions.

## 2. `Source` has no `redistribution` field

Plan 15's quality bar: *"Record `redistribution: full | extract | forbidden` on
each source."*

`schemas/source/source.schema.json` has no such property and is
`additionalProperties: false`. There is a `licence` string, but licence and
redistribution posture are different facts: LEGI and BOFiP are both **Licence
Ouverte 2.0**, which *permits* a full dated mirror, while this repository has
not built one and therefore actually redistributes only extracts. Collapsing
the two loses exactly the distinction plan 15 is asking us to record, and a
consumer cannot tell "we may not mirror this" from "we have not mirrored this
yet".

Requested:

```json
"redistribution": { "enum": ["full", "extract", "forbidden", "unknown"] }
```

on `source.schema.json`, defaulting to nothing (absent means unknown). Adding
it to `source-version.schema.json` too would let a single archived capture
declare a posture that differs from its source's.

**Workaround used in P0-3-01.** Every France and EU source record carries
`redistribution: extract` as the leading token of its free-text `notes`. This
is a stopgap, not a convention worth keeping: it is unparseable in practice and
invisible to the schema. It is documented in
[`jurisdictions/france/RESEARCH.md`](../../jurisdictions/france/RESEARCH.md),
§3.

---

## Impact if neither is fixed

Item 1 blocks any pack that needs to keep historical text alongside current
text through the mechanism the schema provides for it. The dated-source
workaround scales, but it puts the version relationship in two places
(`supersedes` links and naming convention) instead of one.

Item 2 is lower severity: the information is recorded, just not machine
readable, so the knowledge API (**P0-3-08**) cannot surface redistribution
posture per source.
