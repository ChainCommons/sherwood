# 21 — P1, P2, and ecosystem positioning

**Spec:** §§46, 103–104, 108–109  
**Do not implement in the P0 build** except where P0 schemas already allow extension.

## Positioning (§108)

Do NOT duplicate every capability of commercial crypto-tax products.

Focus where open infrastructure is valuable:

```text
high-quality chain semantics
historical source provenance
legal rule versioning
open calculation logic
explicit ambiguity
transaction reconstruction
evidence generation
small focused tools
professional auditability
privacy
interoperability
```

Existing tax products SHOULD be treated as potential downstream consumers of cleaned data (TOOL-013).

## Tezos product principle (§109)

First release SHOULD feel native to the Tezos community, not generic accounting with Tezos bolted on. Understand: artist, collector, mint, primary, secondary, royalty, marketplace, tez, FA2, baker, wallet, collection — then map into generic economic records.

## P2 scope (§104)

- advanced DeFi
- derivatives

## Schema stability rule

P0 schemas MUST already contain event types, tax domains, nested jurisdictions, reporting rules, and compensation-right events so P1 does not break ledgers.
