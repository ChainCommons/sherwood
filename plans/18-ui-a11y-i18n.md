# 18 — UI, accessibility, internationalization, discoverability

**Spec:** §§94–96, 110  
**Workstream:** G + H  
**Depends on:** tools (08), knowledge (05), workspace (09)  
**P0:** tool-first public UI + knowledge browse/search + workspace sufficient for demos

## UI principles (§94)

SHOULD be: tool-first; evidence-first; low-friction; understandable by non-accountants; transparent; progressive in complexity.

Avoid dashboards overloaded with unexplained tax numbers.

Prefer “Potential issue detected” over “You owe €X” unless the calculation is sufficiently deterministic and sourced.

Architecture before UI (§106): thin interfaces over stable packages. Toolbox MAY ship before rich workspace polish.

## Tool discoverability (§110)

Public home page SHOULD prominently expose Tax Tools:

```text
Wallet Tax Timeline
Historical Valuator
Transaction Explainer
NFT Sale Reconstructor
Artist Revenue
Collector Activity
Wallet Mapper
Data Health Check
Guidance Time Machine
Rule Diff
Evidence Pack
```

Users SHOULD arrive via search engine and use one tool immediately. Each tool: unique URL, title, meta description, no login wall.

Also expose Knowledge: jurisdictions, maturity badges, as-of search.

## Accessibility (§95)

Public interfaces SHOULD target **WCAG 2.2 AA**.

Warnings, confidence, and review status MUST NOT rely on color alone (text labels + icons + patterns).

Keyboard access for tool forms, ledger tables, finding traces. Visible focus. Form errors in text.

## Internationalization (§96)

- MUST preserve source original language
- Translations MUST remain separate records
- Machine translations MUST be labeled
- Original legal text MUST remain accessible where redistribution rules allow

UI chrome: English first in P0; French UI strings SHOULD follow quickly because France is the proving jurisdiction (P1 multilingual explanations per §103). Do not translate legal extracts in place.

Date/number formatting: use locale separately from legal source language.

## Implementation tasks

1. Design tokens + layout: home, tool frame, knowledge article, workspace.
2. Maturity, certainty, review-status, fact-status chips with text.
3. As-of date control on knowledge search.
4. Disclaimer component on tools and findings.
5. a11y: landmark regions, table captions, contrast audit.
6. i18n: `source.original_language` displayed; `translation.machine: true` banner.

## Browser verification (when implementing)

Exercise each P0 tool end-to-end; knowledge as-of search; workspace demo path; desktop and a narrow viewport. Do not ship on screenshot-only.
